# SIMU5G CORE PATCHES — tracked on simu5g-1.5.0's nasctime-core-patches
# branch, NOT applied by hand per this inventory. See that repo's git log
# for the authoritative list; summary as of this session:
# ============================================================================
#
# src/simu5g/corenetwork/gtp/GtpUser.ned / .h / .cc
#   Added forceTunnelPeer (string, default ""). Bypasses TFT/Binder-based
#   tunnel routing entirely when set; guarded to UPF/PGW ownerType only.
#   Committed this session. Ported from the v1.4.1-sdap-2-era design,
#   adapted for v1.5.0's Qfi strong-typedef (was uint8_t) and
#   Binder::getServingNodeOrSelf() (renamed from getNextHop()).
#
# src/simu5g/stack/mac/LteMacEnb.cc
#   Guarded an unsigned-int underflow in macSduRequest() when a CID's
#   scheduler grant is smaller than MAC_HEADER (2 bytes) -- was silently
#   wrapping to ~4.29e9 and crashing with a misleading "configured
#   queueSize too low" cRuntimeError under multi-DRB QOS_PF contention.
#   Candidate for upstream report (not yet filed as of this session).
#
# NOT DONE, confirmed obsolete from the original inventory:
#   "src/stack/NRNicEnbDrb.ned: nrPdcp[numDrbs].multiSession" -- this file
#   does not exist in v1.5.0 (confirmed absent, along with gNodeBSdap and
#   NRNicUeDrb). SDAP/DRB is now hasSdap=true on the standard NrNicEnb/
#   NrNicUe NIC types; there is no multiSession-style parameter anywhere
#   in v1.5.0 (confirmed via grep) -- this entire modification is dead
#   and should not be attempted.
#
# STILL TO COME (DC work, next session):
#   Binder: DC secondary-node registration (registerDcSecondary,
#     getDcNextHop, getDcPrimaryNextHop) -- Binder methods are virtual as
#     of v1.5.0, favor a subclass over a direct patch where practical.
#   LteAmc: DC-secondary check, target getServingNodeOrSelf() (renamed).
#   LtePhyUe: DC-secondary attach logic -- masterId_ renamed to
#     servingNodeId_, and handover logic (likely including the attach
#     hook this needs) was extracted into a new HandoverController
#     submodule under Rrc. Re-read that module before assuming this patch
#     still belongs in LtePhyUe at all.
#   LtePhyBase: destId param on getReceiverGateIndex() for DC secondary
#     routing -- confirmed signature otherwise unchanged, should be
#     low-risk once the above land.
